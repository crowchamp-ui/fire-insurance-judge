# spec.md：火災保険 有責・無責 判定シート

背景と4階層は [課題仮説シート.md](課題仮説シート.md) を参照。

公開URL：https://crowchamp-ui.github.io/fire-insurance-judge/（GitHub Pages。main ブランチにプッシュすると更新される）

## 1. 目的

代理店スタッフの能力を底上げする。スタッフが「この場合はどうなの？」と迷ったとき、スタッフ同士で相談したり作者に聞いたりしなくても、判定の理由とともに自分で答えを出し、お客様に説明できるようにする。

そのため、結論（有責／無責／要確認）だけでなく、チェック項目ごとの結果と理由を必ず表示する。

## 2. 利用者と利用場面

- 利用者：損害保険代理店のスタッフ（保険の専門家ではない）
- 場面：お客様から電話や来店で事故の連絡を受け、契約内容を確認しながら話を聞いているとき。または、同僚から「この場合はどうなの？」と聞かれたとき
- 端末：PC のブラウザ（スマートフォンでも崩れずに使える）

## 3. 画面構成

1 画面のみ。左に入力欄、右に判定結果（狭い画面では縦に並ぶ）。

- **A 契約内容**：保険期間（始期・満期）、保険の対象（建物／家財）、付帯している補償、保険金額、免責金額、風災の支払方式（地震保険はこのツールの対象外）
- **B 事故の内容**：事故発生日、保険金請求日、損害を受けたもの、事故の原因、原因ごとの追加質問、免責事由のチェック
- **C 損害額**
- **判定結果**：有責／無責／要確認の印、支払見込額と計算式、チェック項目ごとの結果と理由
- **お客様向けの説明文**：判定結果から作った説明文（書き換え可）と「説明文をコピー」ボタン
- **事例の読み込み**：架空の事例ボタン
- **利用ログ**（判定シートの下、横幅いっぱい）：「この判定を記録」ボタン、集計、記録の一覧、「CSVで書き出す」ボタン

### 利用ログ

成功の数字「案内の訂正件数」を数えるための記録。1人で使う前提で、記録はブラウザ内（localStorage）に保存し、外部には送信しない。

- **記録するとき**：担当者が「この判定を記録」を押したときだけ（入力が足りないときは押せない）
- **記録する項目**：記録日時、事故発生日、事故の原因、損害を受けたもの（建物／家財）、窓口の見込み（有責／無責／要確認）、支払見込額（無責のときは空）、保険会社の最終判断（あとから入力）
- **記録しない項目**：氏名・住所・証券番号など個人情報。受付番号も付けない（案件は事故発生日と原因で探す）
- **案内の訂正**：最終判断が入力された記録のうち、窓口の見込み（有責／無責）と最終判断が食い違ったもの。「要確認」と案内した記録は「対象外」として数えない
- **集計**：記録件数／最終判断を入力済みの件数／案内の訂正件数
- **一覧**：新しい順。最終判断はその場で選んで保存。削除は2段階（「削除」→「本当に削除」）
- **CSV**：Excel で文字化けしない BOM 付き UTF-8。列は 記録日時・事故発生日・事故の原因・損害を受けたもの・窓口の見込み・支払見込額（万円）・保険会社の最終判断・案内の訂正
- **記録についての説明**を常に表示する（保存場所、外部に送信しないこと、個人情報を記録しないこと、閲覧データを消すと記録も消えるので定期的にCSVで書き出すこと）
- 保存できない環境（プライベートウィンドウ等）でも画面は動き、その旨を表示する

### お客様向けの説明文

メール・手紙の本文に貼る書き言葉。挨拶・署名は担当者が書き足す。次の4段落で作る。

| 段落 | 内容 |
|---|---|
| ① 事故の概要 | 「◯年◯月◯日に発生した（原因）による（建物／家財）の損害について、ご契約内容をもとに確認いたしました。」 |
| ② 見込み | 有責：お支払い対象となる見込み／無責：お支払い対象とならない見込み／要確認：次の点を確認したうえで改めて案内 |
| ③ 理由 | 有責：対象となる補償／無責：不適合になった項目の理由／要確認：確認が必要な点（いずれも箇条書き） |
| ④ 締め | 最終的なお支払いの可否は保険会社の損害調査で決まること。有責のときは、お支払い額も損害調査で決まること |

- **金額は入れない**（金額は損害調査で変わり、窓口で伝えると案内の訂正につながりやすいため）
- 理由・確認点の文は、窓口向けの説明とは別に、チェック項目ごとにお客様向けの文を用意する
- 事故発生日・請求日・保険期間・損害額などの入力が足りないときは、説明文を作らず、コピーボタンを押せなくする
- コピーできない環境では、説明文を全選択して、手でコピーするよう案内する

## 4. 判定ロジック

チェック項目を次の順に評価する。各項目は「適合／不適合／要確認／対象外」のいずれか。

| # | 項目 | 不適合（無責）になる条件 |
|---|---|---|
| 1 | 請求期限 | 請求日が事故発生日から3年を超える（保険法95条） |
| 2 | 保険期間 | 事故発生日が始期より前、または満期以降 |
| 3 | 保険の対象 | 損害を受けたもの（建物／家財）が契約の対象に含まれない |
| 4 | 免責事由 | 故意・重大な過失・法令違反／戦争・核燃料物質等／経年劣化・さび・腐食・虫食い等 |
| 5 | 補償範囲 | 事故原因に対応する補償が付帯されていない。地震・噴火・津波による損害（地震が原因の火災・破裂爆発を含む）は火災保険では補償されないため、常に不適合（地震保険の窓口へ案内。地震が原因の火災では地震火災費用保険金の可能性を添える） |
| 6 | 支払基準 | 原因ごとの基準（下表）を満たさない |
| 7 | 支払額の算定 | 損害額が免責金額以下。風災のフランチャイズ方式で損害額20万円未満 |

原因ごとの支払基準（6）：

| 原因 | 追加質問 | 不適合 | 要確認 |
|---|---|---|---|
| 火災・破裂爆発 | 地震等が原因か | （はい → 地震・噴火・津波による損害として扱う） | 不明 |
| 風災・雹災・雪災 | 建物外部に破損があるか | いいえ（吹込み・雨漏りのみ） | 不明 |
| 水災 | 浸水・損害の程度 | 床上浸水・地盤面から45cm超・損害30%以上のいずれにも当たらない | 不明 |
| 水濡れ | 損害は給排水設備そのものだけか | はい | 不明 |
| 物体の衝突 | 自分が運転する車両か | はい | 不明 |
| 盗難 | 警察へ被害届を出したか | — | いいえ・不明 |
| 破損・汚損 | 機能に支障のない外観上の損傷だけか | はい | 不明 |

総合判定：

- 不適合が1つでもある → **無責**
- 不適合がなく、要確認が1つでもある → **要確認**
- すべて適合（または対象外） → **有責**

支払見込額：

- 通常：損害額 − 免責金額（保険金額が上限）
- 風災のフランチャイズ方式：損害額20万円以上なら損害額の全額
- 無責のときは表示しない。要確認のときは「確認事項が解決した場合」と添える

## 5. 受入基準

- 事例「台風で屋根瓦が飛散」を読み込むと、**有責**、支払見込額 40万円（45万円 − 5万円）と表示される
- 事例「古い屋根からの雨漏り」を読み込むと、**無責**と表示され、免責事由（経年劣化）と支払基準（外部破損なし）が不適合になる
- 事例「豪雨で床下浸水」を読み込むと、**無責**と表示され、支払基準が不適合になる
- 事例「子どもがテレビを倒した」を読み込むと、**有責**、支払見込額 7万円（12万円 − 5万円）と表示される
- 事例「空き巣被害」を読み込むと、**要確認**と表示される
- 事例「地震で外壁にひび」を読み込むと、**無責**と表示され、補償範囲が不適合（火災保険では補償されない）になる
- 事故の原因を火災にして「地震等が原因」と答えると、**無責**になり、地震火災費用保険金の案内が表示される
- 地震の事例の説明文には、火災保険では補償されないことと、地震保険は別途案内する旨が入る
- 事故発生日を保険期間の外にすると、**無責**になり、保険期間が不適合と表示される
- 入力を変えると、ボタンを押さずに判定結果が更新される
- 幅 400px の画面でも横スクロールが出ない
- 有責の事例では、説明文に「お支払い対象となる見込み」が入り、金額（「万円」）は入らない
- 無責の事例では、説明文に不適合になった理由が入る（例：雨漏りの事例なら経年劣化と吹き込み・雨漏りの理由）
- 要確認の事例では、説明文に確認が必要な点が入る（例：空き巣の事例なら警察への被害届）
- 説明文には事故発生日と「最終的なお支払いの可否は保険会社の損害調査で決まる」旨が入る
- 入力が足りないときは説明文を作らず、コピーボタンを押せない
- 「説明文をコピー」を押すと、説明文がコピーされ「コピーしました」と表示される
- 「この判定を記録」を押すと一覧に1行増え、「記録しました」と表示される。入力が足りないときは押せない
- 記録1行には決めた項目だけが入り、個人情報の欄はない。無責の記録には支払見込額が入らない
- 有責と案内した記録に最終判断「無責」を入れると（またはその逆）、案内の訂正が1件増える。同じなら増えない。要確認の記録は「対象外」で数えない
- ページを読み込み直しても記録が残っている
- 「削除」→「本当に削除」で1件削除できる
- 「CSVで書き出す」で、見出し行つきのCSVが保存され、Excel で開いても文字化けしない
- 幅 400px の画面では、一覧の中だけが横にスクロールし、ページ全体ははみ出さない

確かめ方と結果は [test.md](test.md)。判定の計算に関する項目は `node --test` で自動で確かめる。

## 6. 非機能要件

- サーバーを持たない（HTML／CSS／JavaScript のみ）。入力内容は外部に送信しない
- 個人情報は入力させない。事例はすべて架空
- 画面には「一般的な約款に基づく目安であり、最終判断は保険会社」と常に表示する
- ライトモード・ダークモードの両方で読める

ファイル構成：

| ファイル | 役割 |
|---|---|
| `index.html` | 画面。入力欄の値を集めて判定ロジックに渡し、結果を表示する |
| `js/judge.js` | 判定ロジック、事故原因と追加質問の一覧、架空の事例。画面に依存しない |
| `tests/judge.test.mjs` | 受入基準の自動テスト（Node.js の標準機能のみ使用） |

## 7. 成功を測る数字

2つの数字を、毎月末に導入前1か月と導入後1か月で比べる。導入前の件数と目標は課題仮説シートに書く。

- **作者への問い合わせ件数**（月あたり）：スタッフから作者に判断を聞かれた件数。Core「能力の底上げ」に一番近い数字
  - 測り方：作者が手で数える。問い合わせを受けたら手帳やメモに日付と内容を1行書き、月末に数える。ツールでは記録しない
- **案内の訂正件数**（月あたり）：窓口で伝えた見込みと保険会社の最終判断が、有責↔無責で食い違った件数
  - 測り方：お客様に案内したら「この判定を記録」を押す。保険会社の最終判断が出たら一覧で入力する。毎月末に利用ログの「案内の訂正」の件数を見る（CSVで書き出して保存しておく）
  - 導入前の件数は、利用ログでは測れないため、作者が今までの記録や感覚から課題仮説シートに書く

## 8. やらないこと

- 最終的な支払可否の決定
- 氏名・住所・証券番号など個人情報の入力・保存
- 臨時費用保険金・残存物取片づけ費用など費用保険金の計算（あとで決める）
- 特定の保険会社の約款の再現（あとで決める）
- 地震保険の判定（損害区分は、保険会社の調査員・鑑定人が非公開の点数方式で現地査定して決まる。区分が決まれば支払額は定率で決まるため、窓口ツールで扱う意味がない）

## 9. あとで決めること

- 保険会社ごとの約款設定を持つか
- 費用保険金を計算に含めるか
