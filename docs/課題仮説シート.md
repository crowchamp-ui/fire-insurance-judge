# 課題仮説シート：火災保険 有責・無責 判定シート

> 「要記入」の欄は、作者が自分で決めて埋める。AIは推測で埋めない。

## 4階層

| 層 | 内容 |
|---|---|
| Core | 窓口での案内の誤りを減らし、お客様に「最初に聞いた話と違う」と思わせない |
| Why | 代理店・窓口の担当者が、事故の連絡を受けたその場で、約款を調べなくても有責・無責の見込みと理由をお客様に説明できる状態にする |
| What | 契約内容と事故状況を入力すると、有責／無責／要確認の見込みと判定根拠が出る判定シート（詳細は spec.md） |
| How | HTML／CSS／JavaScript のみのブラウザアプリ。GitHub Pages で公開（詳細は spec.md） |

## 対象者

- 損害保険代理店・保険の窓口で、火災保険の事故連絡を最初に受ける担当者
- 保険の専門家ではなく、約款の細かい条件までは覚えていない

## 今の困りごと（課題）

1. **お客様への説明**：「保険は出ますか」と聞かれても、その場で答えられない。無責になりそうな場合に、なぜ出ないのかをうまく説明できない
2. **約款を調べる手間**：補償の範囲や免責の条件を、約款から探すのに時間がかかる

## 仮説

- 判定の流れ（請求期限 → 保険期間 → 保険の対象 → 免責事由 → 補償範囲 → 原因ごとの基準 → 支払額）を順にたどれば、窓口でも見込みを立てられる
- 判定の理由を項目ごとに文章で示せば、お客様への説明にそのまま使える
- その結果、窓口の見込みと保険会社の最終判断の食い違い（案内の訂正）が減る

## 成功条件（KPI）

| 指標 | 内容 | いつ見るか |
|---|---|---|
| 案内の訂正件数 | 窓口で伝えた見込みと、保険会社の最終判断が食い違った件数（月あたり） | 毎月末。導入前1か月と導入後1か月を比べる |

- 導入前の件数：**要記入**
- 目標：**要記入**（例：導入前の半分以下）

## やらないこと

- 最終的な支払可否の決定（判断の補助にとどめ、最終判断は保険会社）
- お客様の氏名・住所・証券番号など個人情報の入力や保存
- 特定の保険会社の約款の再現（一般的な約款の基準で判定する）
