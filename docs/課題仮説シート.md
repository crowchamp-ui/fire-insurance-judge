# 課題仮説シート：火災保険 有責・無責 判定シート

> 「要記入」の欄は、作者が自分で決めて埋める。AIは推測で埋めない。

## 4階層

| 層 | 内容 |
|---|---|
| Core | **代理店スタッフの能力を底上げする**。一人ひとりが自分で正しく判断し、お客様に案内できるようにする（その結果、案内の誤りが減り、お客様に「最初に聞いた話と違う」と思わせない） |
| Why | 代理店スタッフが「この場合はどうなの？」と迷ったとき、わからない者同士で相談したり、作者が介入して説明したりしなくても、判定の理由とともに自分で答えを出し、お客様に説明できる状態にする |
| What | 契約内容と事故状況を入力すると、有責／無責／要確認の見込みと判定根拠が出る判定シート（詳細は spec.md） |
| How | HTML／CSS／JavaScript のみのブラウザアプリ。GitHub Pages で公開（詳細は spec.md） |

## 対象者

- 損害保険代理店・保険の窓口で、火災保険の事故連絡を最初に受ける担当者
- 保険の専門家ではなく、約款の細かい条件までは覚えていない

## 今の困りごと（課題）

1. **相談の二重の時間の無駄**（いちばん大きい問題）：「この場合はどうなの？」と聞かれると、わからない者同士で相談して時間がかかる。結局、作者が介入して説明することになり、相談の時間と説明の時間の二重の無駄が生じている。スタッフ自身の判断力も育たない
2. **お客様への説明**：「保険は出ますか」と聞かれても、その場で答えられない。無責になりそうな場合に、なぜ出ないのかをうまく説明できない
3. **約款を調べる手間**：補償の範囲や免責の条件を、約款から探すのに時間がかかる

## 仮説

- 判定の流れ（請求期限 → 保険期間 → 保険の対象 → 免責事由 → 補償範囲 → 原因ごとの基準 → 支払額）を順にたどれば、窓口でも見込みを立てられる
- 判定の理由を項目ごとに文章で示せば、お客様への説明にそのまま使える
- 結論だけでなく「どの項目で、なぜそうなるか」を毎回目にすることで、スタッフが判断の筋道を覚え、ツールがなくても判断できるようになっていく
- その結果、スタッフ同士の相談や作者への問い合わせが減り、窓口の見込みと保険会社の最終判断の食い違い（案内の訂正）も減る

## 成功条件（KPI）

| 指標 | 内容 | いつ見るか |
|---|---|---|
| 案内の訂正件数 | 窓口で伝えた見込みと、保険会社の最終判断が食い違った件数（月あたり） | 毎月末。導入前1か月と導入後1か月を比べる |

- 導入前の件数：**要記入**
- 目標：**要記入**（例：導入前の半分以下）

> Core を「能力の底上げ」にしたため、それに近い数字（例：スタッフから作者への問い合わせ件数）を KPI に加えるかは **要検討**（作者が決める）。

## やらないこと

- 最終的な支払可否の決定（判断の補助にとどめ、最終判断は保険会社）
- お客様の氏名・住所・証券番号など個人情報の入力や保存
- 特定の保険会社の約款の再現（一般的な約款の基準で判定する）
- 地震保険の判定（下の「見直しの記録」を参照）

## 見直しの記録

### 2026-11-05：Core を「代理店スタッフの能力の底上げ」に書き直した（Core の見直し）

- **それまで**：Core は「窓口での案内の誤りを減らす」だった
- **分かったこと**（作者が提出物を見直す中で）
  - 本当の問題は、スタッフが「この場合はどうなの？」と迷ったときに、わからない者同士で相談して時間がかかり、さらに作者が介入して説明するという二重の時間の無駄にある
  - 案内の誤りを減らすことは大事だが、それはスタッフ一人ひとりが正しく判断できるようになった結果として起きること
- **戻った階層**：Core（Why も合わせて書き直した）
- **What への影響**：今の機能（項目ごとの判定理由、お客様向けの説明文）は、スタッフが判断の筋道を学ぶ材料にもなるため、作り直しは不要と判断。能力の底上げに近い数字を KPI に加えるかは要検討

### 2026-11-05：地震保険の判定をなくした（What の見直し）

- **それまで**：損害区分（全損・大半損・小半損・一部損）を入力すると、地震保険金額 × 定率で支払見込額を出していた
- **分かったこと**（作者の実務経験から）
  - 窓口が本当に知りたいのは「どの区分になるか」の判断だが、区分は保険会社の調査員・鑑定人が現地で点数方式により査定して決まる。その点数表は基本的に非公開
  - 区分が分かっていれば、地震保険は定率払いなので、有責かどうかも支払額もツールを使うまでもない
  - つまり、この機能は誰の役にも立たない。区分を窓口で予想して伝えると、外れたときに案内の訂正になり、Core にも反する
- **戻った階層**：What（Core・Why はそのまま）
- **直したこと**：地震保険の補償・区分・金額の計算をなくし、火災保険の判定だけにした。地震・噴火・津波による損害は「火災保険では補償されない（無責）」と判定し、地震保険の窓口へ案内する
